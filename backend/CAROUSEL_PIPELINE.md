# Карусели и сторис

По умолчанию `CAROUSEL_ENGINE=blocks`. `karpix` остаётся явно выбираемым старым движком; описанный ниже редакторский процесс относится к `blocks`.

## Редакторский процесс

1. `carousel_editor.build_plan`: LLM извлекает самостоятельные пункты исходника с дословными опорами, формулирует обещание обложки, выбирает порядок битов и формат каждого. Число слайдов не вычисляется по словам. Текущий бюджет — обложка, 1–5 основных слайдов, CTA. Несколько пунктов могут быть раскрыты на одном слайде, но каждый должен оставаться различимым.
2. `compose_reviewed_deck`: LLM пишет слайды по плану. `beat_id` связывает основной слайд с битом. `paragraphs` задаёт смысловые абзацы, необязательный `title_lines` — смысловые строки заголовка. Эти поля не вычисляются нарезкой текста.
3. `review_deck`: отдельный вызов LLM проверяет обещание обложки, раскрытие пунктов, связность, факты, формат и редактуру. Для каждого пункта нужны номер основного слайда и точная цитата из него. Код проверяет полноту ссылок; смысл оценивает модель. Это не гарантирует безошибочность LLM, поэтому согласование текста человеком сохраняется.
4. Рендер обоих размеров. При `SlideLayoutError` модель получает замечание и переписывает слайды по тому же плану; результат снова проходит редакторскую проверку. Пересоздаются все варианты платформы, чтобы картинки и подписи не расходились. Системные ошибки браузера не запускают переписывание текста.

Планирование: до двух попыток. Написание с редакторской проверкой: до трёх попыток. Исправление после рендера: один цикл. Если исправить не удалось, задача завершается ошибкой, а не сохраняет механически собранную карусель. `build_fallback_deck` используется только при явном офлайн smoke-тесте.

`editorial_plan` и `editorial_review` сохраняются рядом со `slides` в `platform_texts` для диагностики. CTA для карусели и сторис берутся из соответствующих настроек.

## Типографика

Видимый текст экранируется. Короткие предлоги/союзы связываются неразрывным пробелом со следующим словом; число — с обозначением. Слова не разрываются произвольно, автоматические переносы с дефисом отключены. Заголовки балансируются браузером, основной текст использует `text-wrap: pretty`. Рендер сохраняет заданные моделью абзацы. Проверка после загрузки шрифтов учитывает вертикальное и горизонтальное переполнение; уменьшение ограничено коэффициентом 0.82. Более сильное переполнение возвращается на редактуру.

## Проверка

`PYTHONPATH=backend python3 -m pytest backend/tests/test_carousel_editor.py backend/tests/test_carousel_blocks.py backend/tests/test_blocks_pipeline.py backend/tests/test_blocks_html.py backend/tests/test_html_slide_renderer.py`

Тесты используют управляемые ответы модели и реальный Chromium для проверки вёрстки. Для проверки качества живой LLM нужен `OPENROUTER_API_KEY`; запуск: `PYTHONPATH=backend python3 backend/scripts/run_blocks_smoke.py --text-file /path/to/source.txt --out /path/to/output`. Скрипт не публикует материалы.


## Форматы по соцсетям

В «Каналы → Карусели и сторис» у каждой активной соцсети есть независимые
переключатели каруселей и сторис. После «Сохранить настройки» выбор хранится
в `postmypost_project_settings.carousel_formats` отдельно для пользователя и проекта.
Например: `{"telegram": {"carousel": true, "story": false}}`.

- Отсутствующие настройки сохраняют прежнее поведение: включены все поддерживаемые форматы.
- Для TikTok доступна только карусель; сторис не генерируются и не публикуются.
- CTA требуется только для включённых форматов. Отключение сохраняет введённый CTA.
- Ручное и ежедневное создание черновиков пропускают соцсети с обоими выключенными форматами.
- Генерация читает текущие настройки, рендерит только выбранные форматы и допускает только сторис.
- Перед планированием настройки читаются повторно: отключённые сторис не отправляются,
  даже если их изображения уже были созданы в старом черновике.
- Публикации, уже поставленные в расписание PostMyPost, автоматически не отменяются.
- Включение нового формата не создаёт изображения задним числом: нужна новая генерация.

API проекта принимает `carousel_formats` как словарь соцсетей с булевыми полями
`carousel` и `story`; частичное обновление сохраняет остальные предпочтения.
